# Security policy

## Supported version

Only the latest commit on `main` is supported. Generated catalog files and older branches do not receive separate security fixes.

## Reporting a vulnerability

Do not open a public issue with exploit details, credentials, client data, firm data, tax records, or personal information.

Repository collaborators should open a private GitHub security advisory. If that surface is unavailable, contact a repository owner without including sensitive details in the first message.

Include the affected asset or build path, the commit tested, the security impact, a minimal reproduction, and any known mitigation. Use fabricated examples. Do not submit production tax data or internal firm material.

## Scope

Reports may cover the offline catalog build, generated HTML, validation gaps that permit unsafe active content, secret exposure, or unsafe instructions in an asset. Content-quality disagreements without a security impact belong in the normal issue workflow.

## Response

This project does not promise a public response-time SLA. An owner will confirm receipt, assess impact, coordinate a fix when needed, and agree on disclosure timing before sensitive details are published.
